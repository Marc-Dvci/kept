# Release evidence checklist

The [Codegeist rules](https://codegeist2026.devpost.com/rules) require a working
Forge app installable in the judge's environment, an installation link and a
public YouTube demonstration with actual target-platform footage. The deadline is
22 December 2026 at 12:00 PST, or 21:00 Paris. Judges need not watch beyond three
minutes. A static replay does not substitute for the Forge installation.

## Current evidence

The shared domain engine, browser replay, native adapters, manifest, tests and
source materials are implemented. Live Forge registration/deployment remain gated
by the explicit zero-spend policy. Synthetic checks are separate from runtime proof.

## Required protected-site run

| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Provider billing protection | Real exempt sandbox/hard zero cap, verified scope and expiry                                                                 |
| Fresh installation          | Registered UUID, successful install, setup steps and working judge link                                                      |
| Demo load                   | Actual created issue/version/comment counts; permission failures and retry result                                            |
| Capture                     | Genuine public JSM comment, edited-source refusal, internal/customer comment refusal, confirmed customer/date/work/owner     |
| Planning                    | Direct issue version reassignment, shared version-date update and sprint change; actual canonical observations               |
| Native field formats        | Structured/versioned sprint data, configured empty flag, absent/malformed fields and property timestamp/fetch-time separation |
| Alerts                      | One in-app alert per relevant change, correct owner, duplicate-event handling and review attribution                         |
| Event recurrence            | Duplicate delivery yields one alert; later return to the same risky date yields a new occurrence; concurrent snapshots retain the newest data |
| Discovery                   | More than one 20-reference page, request-bound scope, expiry, direct loading of older replies and current-user permissions |
| Permission matrix           | Reader/editor/admin; hidden source; one hidden required work item; Rovo/MCP and export respect the same boundary             |
| Concurrency                 | Two independent users write one version; one succeeds, one must refresh; delayed event cannot roll back current observations |
| Customer delivery           | Done without availability proof remains at risk; timely evidence becomes kept; late delivery stays broken                    |
| Agreed amendment            | Previous date and agreement evidence remain; original outcome is visible                                                     |
| Graph                       | Synthetic documents accepted and read in Search/Rovo; real-record refusal; disconnect cleanup                                |
| Agents/MCP                  | Actual entitlement, three authenticated read-only tool calls, evidence citations and no write action                         |
| Runtime                     | Cold/warm timing, 403/404/429/503, storage faults, iframe/mobile layout and observed population limits                       |
| Presentation                | Public captioned film, actual Forge workflow, final cover and sponsor-surface gallery image                                  |

Record date, environment, role, input, expectation, observed result, duration and
scrubbed log/screenshot for each. No customer records or tokens belong in public
evidence. Run an officer/customer-success walkthrough and record objections; no
time-saving or churn claim is supported by the synthetic tests.

## Marketplace review pack

The intended lead bonus is Marketplace. A listing or review-ticket link is needed
before claiming entry into that bonus. Prepare a partner profile, privacy and terms
URLs, documentation, support contact, screenshots and the security/privacy answers.
They require the registered app and verified runtime first.

Atlassian's [distribution guide](https://developer.atlassian.com/platform/forge/distribute-your-apps/)
restricts installation-link sharing for apps submitted for listing or licensed.
Resolve judge access with the current rules and Marketplace process before review;
do not disable the only judge link prematurely. No partner agreement was accepted,
listing submitted or Marketplace bonus claimed during this build.

## Production follow-up

Institutional source/CRM identity validation, broader language/date recognition,
reviewed privacy and retention/deletion, live permission revocation tests, workload
tests, durable retry/reconciliation and actual notification-delivery requirements
remain operational release work. The current follow-up channel is the in-app queue.
No scheduled deadline sweep runs while the app is closed; next-open assessment uses
the current clock. The source is a scoped prototype, not a contractual compliance
system or production SLA service.
